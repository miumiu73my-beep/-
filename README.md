# 野菜聖女

現実時間でゆるく育つ野菜畑と、研究所・畑・自宅を行き来するPWAゲームです。

## 実装済み

### STEP 1｜プロジェクトの土台

- PWAの最小構成
- iPhone / iPadの縦画面を基準にしたレイアウト
- `data/`・`assets/`・`screens/`・`save/` の役割分離
- 「研究所」「畑」「自宅」の3画面切り替え
- アプリアイコン
- GitHub Pages向けデプロイWorkflow

### STEP 2｜ゲーム全体の保存データ

IndexedDBを使い、ゲーム全体を1つのversion付きセーブデータとして自動保存します。

保存対象：

- 主人公の任意名
- 一歌・千隼・雨流・朱夏ごとの「対応する受の名前／任意名」呼称モード
- 固定表示する好きなキャラ
- 所持金
- 畑サイズ
- 各畑マスの状態
- 種・収穫物
- 野菜の品質関連値
- 研究所の受講・勉強記録
- 最終保存時刻
- 各種設定
- セーブデータのversion

好感度・親密度パラメータは保存データにも作っていません。

`save/schema.js` が保存形式、`save/storage.js` がIndexedDBの読み書きを担当します。
起動時に自動復元し、起動時・30秒ごと・バックグラウンド移行時などに自動保存します。
今後セーブ形式を変更する場合は、`migrateSaveData()` にversionごとの移行処理を追加します。

畑の初期サイズはSTEP 7で正式に3×3とし、所持金を使って4×4、5×5へ段階的に拡張できます。

### STEP 3｜現実時間・カレンダー基盤

- 端末の現在日時を取得
- 朝（5:00〜11:59）／昼（12:00〜17:59）／夜（18:00〜4:59）の判定
- 曜日・土日判定
- IndexedDB内の最終保存時刻との差から経過時間を算出
- 自宅画面に現実の年月日・曜日・現在時刻・時間帯を表示

STEP 3で一時的に使用していたlocalStorageの最終保存時刻は、IndexedDBの初回作成時に自動で引き継ぎます。


### STEP 4｜畑システムのMVP

- 3×3の畑マスを実際に操作可能に変更
- 「耕す」「種まき」「水やり」「収穫」「片付け」を実装
- MVP作物として「かぶ」を data/crops.js にデータ化
- タネ価格40G、出荷額90G、成長目安24時間
- STEP 4中は水やり1回で8時間分の成長を進め、3回で収穫可能
- タネ購入→植える→育てる→収穫・即出荷→所持金増加の一連のループを実装
- 野菜が枯れる処理は実装しない
- 畑操作後は既存のIndexedDB自動保存へ反映
- STEP 3以前のセーブデータはversion 2へ移行し、初期資金300Gを付与

### STEP 5｜放置成長

- `plantedAt` に保存した植え付け時刻と、作物ごとの `growMs` から現実時間の成長量を計算
- 起動中は30秒ごとに畑表示を再描画し、成長率を更新
- バックグラウンドから復帰した直後にも経過時間を反映
- アプリを閉じていた時間も、再起動後に `現在時刻 - plantedAt` として自動反映
- 水やりによる `growthMs` は現実時間とは別の「手動成長ボーナス」として加算
- 現実時間と水やりボーナスを合算しても、必要成長時間を超えて二重加算しない
- 長期間放置しても枯れない
- STEP 4の既存セーブ形式をそのまま利用できるため、セーブversionの追加変更は不要

かぶは「現実時間24時間」で自然に収穫可能になり、水やり1回につきさらに8時間分だけ成長を進められます。
そのため、アプリを触らなくても育ち、触りたい時は水やりで少し早められる仕様です。

### STEP 6｜野菜データを本実装

- 原型の12作物を `data/crops.js` の作物マスタへ集約
- 春：かぶ・じゃがいも・キャベツ
- 夏：トマト・とうもろこし・きゅうり
- 秋：にんじん・さつまいも・かぼちゃ
- 冬：だいこん・ほうれん草・はくさい
- 現実の月は、3〜5月=春、6〜8月=夏、9〜11月=秋、12〜2月=冬として扱う
- 季節は旬の表示・並び順に使うが、季節外の購入・種まき・成長を禁止しない
- 季節外でも枯れず、STEP 5の現実時間による放置成長をそのまま利用する
- 各作物に成長日数／成長時間、種価格、基礎売価、品質計算用の `qualityBase` を保持
- `qualityBase` はSTEP 8の品質計算で使う作物側の係数で、現在は全作物1.0の中立値
- STEP 18で、水やりの手動成長ボーナスは必要成長時間の25%に確定。植え付け後1回だけ利用できる
- 畑画面のタネ屋を作物マスタ駆動にし、選択した作物を購入・種まきできる
- 新しい作物は基本的に作物マスタへデータを1件追加するだけで一覧・購入・栽培へ反映される
- STEP 6単体ではセーブ構造を変更していません（STEP 7で畑拡張状態を追加し `SAVE_VERSION = 3` へ更新）

STEP 4のMVPで仮設定していた「かぶ24時間」は、STEP 6から原型の成長日数である3日に置き換えています。

### STEP 7｜畑拡張・経済システム

- 初期畑サイズを3×3に正式決定
- 3×3 → 4×4を1,400G、4×4 → 5×5を4,200Gで拡張
- 拡張段階と価格は `data/economy.js` に集約し、後から値を調整しやすい構成
- 畑拡張時は既存マスを左上の同じ位置に保ったまま、右側・下側へ新しいマスを追加
- 所持金不足時は「あと何G必要か」を畑画面に常時表示し、拡張操作時にも案内
- タネ購入・出荷・畑拡張を同じ所持金で処理し、「育てる→売る→広げる」のゲームループを成立
- 出荷額は `基礎売価 + 品質ボーナス` の共通計算へ変更
- STEP 7で先行用意した品質ボーナスの受け口は、STEP 8の5段階品質システムへ接続済み
- 初期品質「ふつう」ではボーナス0%のため、研究所を使わなくても従来どおりの基礎売価で出荷できる
- 畑拡張状態を保存するため `SAVE_VERSION = 3` へ更新し、旧セーブは自動移行

### STEP 8｜野菜の品質システム

- 品質を「ふつう／良質／上質／特選／極上」の5段階に設定
- 品質計算を `data/quality.js` に分離し、段階・必要スコア・出荷ボーナスを一か所で調整可能
- セーブデータでは `quality.base`（基礎品質）と `quality.researchBonus`（研究所補正）を分離
- 作物ごとの追加補正は `quality.byCrop` に保持できる
- 初期基礎品質は1.0で「ふつう」。研究所を利用しなくても栽培・収穫・出荷は通常どおり成立
- STEP 18の最終調整後、品質段階が上がると出荷額に +5% / +10% / +15% / +20% のボーナス
- 好感度・ログイン頻度・デート回数は品質計算へ一切使用しない
- 畑のタネ屋と収穫メッセージで現在の品質段階を確認可能
- 研究所画面には現在の基礎品質・研究補正・出荷補正を表示
- STEP 9で講座・図書室の操作を `researchBonus` へ接続済み
- 品質データ追加に伴い `SAVE_VERSION = 4` へ更新し、STEP 7以前のセーブは自動移行
- PWAキャッシュを `yasai-seijo-step8-v1` へ更新

品質段階はSTEP 18で以下に確定しました。

| 品質 | 必要スコア | 出荷ボーナス |
| --- | ---: | ---: |
| ふつう | 0.00〜 | +0% |
| 良質 | 1.15〜 | +5% |
| 上質 | 1.30〜 | +10% |
| 特選 | 1.45〜 | +15% |
| 極上 | 1.60〜 | +20% |


### STEP 9｜研究所画面

- 「講座を受ける」を実装。4講座を用意し、各講座は何度でも受講可能
- STEP 18の最終調整後、講座は初回 +0.08、復習 +0.01
- 「図書室で勉強する」を実装。3種類の資料を何度でも読める
- 図書室の勉強1回につき `quality.researchBonus` を +0.02
- 研究補正は +0.60 を上限とし、研究所だけで出荷額が際限なく上がらないようにする
- 講座の初回受講済みIDは既存の `research.completedCourses` に保存し、再受講は制限しない
- 図書室の履歴は既存の `research.studyRecords` に保存
- 研究所の操作結果がSTEP 8の品質段階・出荷ボーナスへ即時反映
- 研究所を使わなくても栽培・収穫・出荷は従来どおり可能
- 好感度・ログイン頻度・デート回数は研究補正に使用しない
- 既存の `player.favoriteCharacter` を利用し、一歌・千隼・雨流・朱夏から研究所の固定キャラを選択可能
- 固定キャラごとに研究所用の短い台詞を表示
- 立ち絵画像はSTEP 10で本実装するため、STEP 9では文字ベースの仮表示
- STEP 2ですでに保存枠を用意していたため、セーブ形式のversionは4のまま変更不要
- PWAキャッシュを `yasai-seijo-step9-v2` へ更新し、`data/research.js` もオフライン対象へ追加

講座・図書室ともに何度でも利用できます。講座は初回の伸びを大きく、復習は小さくし、研究補正は +0.60 で止まります。
`completedCourses` は「その講座を一度以上受けたか」の記録に使い、再受講は復習として扱います。
研究所は品質面を少し有利にする任意コンテンツであり、利用をゲーム進行の条件にはしていません。

### STEP 10｜4人のキャラクター表示システム

- 一歌・千隼・雨流・朱夏の4人を `data/characters.js` に集約
- 研究所・畑・自宅の3画面に共通の固定キャラ表示を追加
- 4人の切り替えボタンから選んだキャラを、既存の `player.favoriteCharacter` に保存
- 未選択・旧セーブでは一歌を表示上の初期キャラとして扱う
- 立ち絵は `assets/characters/portraits/` に分離し、Step 15でぬい写真のPNG / WebPへ差し替え可能
- 背景は `assets/backgrounds/` に研究所・畑・自宅ごとの独立素材として分離
- 畑には4人分のちびキャラレイヤーを追加し、畑操作を妨げず歩き回るアニメーションを実装
- `prefers-reduced-motion` では歩行アニメーションを停止
- 好感度ゲージ・親密度レベル・愛情の増減パラメータは追加していない
- 既存の保存枠を利用するため、セーブversionは4のまま変更なし
- PWAキャッシュを `yasai-seijo-step10-v1` へ更新

現在の立ち絵・ちびキャラは表示確認用の仮SVGです。本番素材への差し替え方法は `assets/characters/README.md` に記載しています。

### STEP 11｜主人公名・呼称設定

- 初回起動時に主人公の任意名を入力する設定ダイアログを表示
- 一歌・千隼・雨流・朱夏ごとに「対応する受の名前／任意名」を個別選択可能
- 対応する受の名前は `data/characters.js` 側で管理（一歌→海、千隼→真琴、雨流→みう、朱夏→小夜）
- 既存の `player.customName` と `player.nameModeByCharacter` を利用してIndexedDBへ自動保存
- 自宅画面から名前・呼び方をいつでも変更可能
- 台詞データに `{{name}}` を置き、表示時に現在の設定に応じて差し替える
- ユーザー入力はHTMLエスケープしてから台詞へ反映
- STEP 2ですでに保存枠を用意していたため、セーブversionは4のまま変更なし
- PWAキャッシュを `yasai-seijo-step11-v1` へ更新し、STEP 11のCSS・名前処理・設定UIもオフライン対象へ追加

同じ台詞テンプレートでも、キャラクターごとの設定に応じて「海／真琴／みう／小夜」または入力した任意名へ置換されます。

### STEP 13｜自宅画面

- STEP 12の台詞エンジンは後回しのまま、STEP 13だけを先行実装
- 自宅に現実の「今月」の月間カレンダーを表示
- 今日の日付・曜日・現在時刻・朝／昼／夜の時間帯を表示
- STEP 10の固定キャラ表示とSTEP 11の名前置換済み自宅台詞を、そのまま自宅の会話枠として利用
- 土日は「デート入口」を表示し、平日は「週末に行ける」案内だけを表示
- デート入口は任意コンテンツで、利用しなくても好感度・野菜品質などに影響しないことを明記
- デート本編・デート先・選択肢などはSTEP 14で実装するため、STEP 13では入口だけを用意
- PWAキャッシュを `yasai-seijo-step13-v1` へ更新し、`assets/step13.css` をオフライン対象へ追加

これで自宅は「現実日時の確認・固定キャラとの会話・週末イベントへの入口」の拠点として成立します。

### STEP 14｜土日のデート機能

- STEP 12の汎用台詞エンジンは未実装のまま、デート専用データとUIを独立して追加
- デートは現実の土日のみ自宅から任意で開始可能。平日は開始処理そのものを受け付けない
- 一歌・千隼・雨流・朱夏それぞれに2件ずつ、計8件のデート先／イベントを `data/dates.js` にデータ化
- 各イベントに複数の選択肢と反応を持たせ、新しいデート先はデータ追加で増やせる構成
- 選択肢には正解・不正解を設けず、会話内容だけが変化する
- デート回数・選択結果・未プレイ状況をセーブデータへ記録せず、好感度・野菜品質・研究補正・所持金などへ一切影響させない
- 今週デートをしなくても、後から責める台詞やペナルティは発生しない
- 高糖度ではあるが穏やかな内容にし、主人公の意思や自由を尊重するイベントのみ収録
- 固定キャラを自宅で切り替えると、そのキャラのデート候補へ即時切り替わる
- PWAキャッシュを `yasai-seijo-step14-v1` へ更新し、`data/dates.js` と `assets/step14.css` をオフライン対象へ追加

デートは完全な任意コンテンツとして成立し、プレイの有無や選択内容がゲーム上の愛情・性能・進行条件にならない設計です。

### STEP 16｜自動保存・バックアップ

- STEP 12（汎用台詞エンジン）とSTEP 15（本番ビジュアル素材）は未実装のまま、STEP 16だけを先行実装
- 畑・研究所・名前・固定キャラなどの変更時に既存どおり自動保存し、起動中も30秒ごとに保存
- バックグラウンド移行・pagehide・beforeunload・freeze時にも終了直前の保存を試みる
- 自宅画面に「自動保存・バックアップ」カードを追加し、手動保存・JSON書き出し・JSON読み込み・端末内バックアップ復元を利用可能
- 書き出しJSONには専用formatとformatVersionを持たせ、インポート時にゲームのセーブ形式・version・主要領域を検証
- 旧versionのセーブは既存の `migrateSaveData()` を通し、現在の `SAVE_VERSION` へ移行してから保存
- メインセーブとは別に「最後に正常だったコピー」を保持し、さらに一定間隔で最大5世代の端末内バックアップを保存
- メインセーブが破損した場合は、最後に正常だったコピー→世代バックアップの順に自動復旧を試みる
- 読み込めない元データは別レコードへ退避し、有効な復旧データが無い場合も勝手にメインセーブを上書きしない
- 復旧不能時はJSONインポートを選べるようにし、初期化しか選べない状態を避ける
- PWAキャッシュを `yasai-seijo-step16-v1` へ更新し、STEP 16のCSSと保存管理UIもオフライン対象へ追加

通常利用では手動セーブを意識する必要はありません。端末移行・念のための保管・復旧時だけJSONバックアップを使う想定です。

### STEP 17｜PWA・オフライン対応

- `manifest.webmanifest` にアプリID・起動URL・scope・`display: standalone`・縦画面向け設定を明示
- 既存の180 / 192 / 512系アプリアイコンをPWAとiPhone / iPadのホーム画面用アイコンとして利用
- HTML・CSS・JavaScript・Web App Manifest・背景画像・キャラクター画像・アイコンをService Workerのアプリシェルとして事前キャッシュ
- 将来追加されるJSON・画像・Webフォント等も、同一アプリscope内で実際に読み込まれたものはランタイムキャッシュできる構成
- 画面遷移（navigation）はネットワーク優先にし、通信できない場合は保存済みの`index.html`へフォールバック
- IndexedDBのセーブデータは通信なしでも従来どおり読み込めるため、オフライン時も保存済み状態から基本プレイ可能
- キャッシュ名を`yasai-seijo-*`に限定して世代管理し、更新時は「野菜聖女」の古いキャッシュだけを削除
- 同一GitHub Pagesドメイン上にある別PWAのCache Storageを誤って削除しないように修正
- STEP 12（汎用台詞エンジン）とSTEP 15（本番ビジュアル素材）は未実装のまま維持

Service Workerのキャッシュ世代は`step17-v1`です。新しい版を公開する際はキャッシュ世代を更新することで、古いアプリシェルが残り続けないようにします。

### STEP 18｜ゲームバランス調整

STEP 12（汎用台詞エンジン）とSTEP 15（本番ビジュアル素材）は未実装のまま、ゲーム進行に関わる数値だけを最終調整しました。

- 野菜の自然成長時間を12〜36時間に調整。放置だけでも最後まで育つ
- 水やりは植え付け後1回だけ行え、必要成長時間の25%ぶんを即時に進める
- 水やり連打だけで即収穫できる状態を解消しつつ、短時間プレイでも成長率が目に見えて進む
- 種価格・売価を成長時間に合わせて再調整し、長時間作物ほど利益が少し高くなるようにした
- 畑拡張価格を1,400G / 4,200Gに調整
- 品質ボーナスを +0% / +5% / +10% / +15% / +20% に抑え、研究所が有利でも必須にならない幅へ調整
- 講座は初回 +0.08、復習 +0.01、図書室は +0.02。研究補正は +0.60 で上限
- 現実時間による成長に上限やログイン要求を設けず、数日〜数週間ぶりでもペナルティなしで再開できる
- 未プレイ期間に対する減収・枯死・維持費・連続ログイン損失などは追加しない

## 初めて遊ぶとき

1. 初回起動時に主人公の任意名を入力します。
2. 一歌・千隼・雨流・朱夏ごとに、「対応する受の名前」または「任意名」のどちらで呼ばれるかを選びます。
3. 「この設定で始める」を押すと畑へ進みます。
4. 畑の「タネ屋」で育てたい野菜を選び、「1個買う」でタネを購入します。
5. 「耕す」を選び、空いている畑マスをタップします。
6. 「種まき」を選び、同じ畑マスをタップします。
7. 必要なら「水やり」を1回だけ行えます。水やりをしなくても、野菜は現実時間で成長します。
8. 「収穫できます」と表示されたら「収穫」を選んで畑マスをタップします。収穫物はその場で出荷され、所持金へ反映されます。

野菜は季節外でも枯れません。数日～数週間アプリを開かなくても、未プレイによる減収・枯死・好感度低下などはありません。

## PWAとしてインストールする

GitHub Pagesへデプロイされたゲームを、**iPhone / iPadのSafari**で開きます。

1. Safari下部または上部の「共有」をタップします。
2. 共有メニューから「ホーム画面に追加」を選びます。
3. 表示名が「野菜聖女」になっていることを確認します。
4. 「追加」をタップします。
5. ホーム画面の「野菜聖女」アイコンから起動します。

ホーム画面から起動すると `display: standalone` のPWAとして動作します。
初回に必要なファイルがキャッシュされた後は、通信が不安定な状況でも保存済みデータを使って基本プレイできます。

アプリ更新後に古い表示が残る場合は、一度Safari側でページを開いて再読み込みしてから、ホーム画面のPWAを開き直してください。

## セーブデータ仕様

セーブデータは、基本的に**この端末のIndexedDB**へ保存します。
現在のセーブ形式は `SAVE_VERSION = 4` です。

主な保存内容：

- 主人公の任意名
- 4人それぞれの呼称モード
- 固定表示するキャラクター
- 所持金
- 畑の拡張段階・各畑マスの状態
- タネ・収穫物などの所持情報
- 野菜の品質関連値
- 研究所の受講・勉強記録
- 最終保存時刻
- 各種設定
- セーブデータのversion

好感度・親密度・ログイン連続日数・デート回数など、愛情を上下させるための値は保存しません。

保存タイミング：

- ゲーム内の状態変更後
- 起動中は約30秒ごと
- バックグラウンド移行時
- `pagehide` / `beforeunload` / `freeze` など終了直前のタイミング

古いセーブデータは、`save/schema.js` の `migrateSaveData()` で現在のversionへ移行します。

## バックアップと復元

自宅画面の「自動保存・バックアップ」から操作できます。

### JSONを書き出す

「JSONを書き出す」を押すと、現在のセーブデータをファイルとして保存できます。

端末移行、ブラウザデータ削除前、大きなアップデート前などは、念のためJSONを書き出して保管してください。

### JSONを読み込む

「JSONを読み込む」から、以前書き出したバックアップを選べます。

読み込み時は、

- バックアップ形式
- セーブversion
- 主要な保存領域

を検証し、古いversionはmigrationを通してから保存します。

### 端末内バックアップ

メインセーブとは別に、

- 最後に正常だったコピー
- 最大5世代の端末内バックアップ

を保持します。

メインセーブが破損している場合は、最後に正常だったコピー、その後に世代バックアップの順で自動復旧を試みます。
自宅画面から「端末内バックアップから復元」を手動で選ぶこともできます。

### 注意

IndexedDBと端末内バックアップは同じブラウザ／端末の保存領域にあります。
SafariのWebサイトデータを削除した場合や端末を初期化した場合に備えるには、**JSON書き出しを別の場所へ保管する方法が最も確実**です。
